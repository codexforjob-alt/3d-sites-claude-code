# КЕДР

Одностраничный сайт ресторана с дровяной печью и суши-стойкой. Статическая сборка
Vite, ванильные ES-модули, без фреймворка — хостится где угодно, в том числе на
обычном шаред-хостинге.

**Всё содержимое вымышлено.** Список того, что обязательно заменить, — в конце файла.

---

## Запуск

```bash
npm install
```

```bash
npm run dev
```

Дев-сервер поднимается на `http://127.0.0.1:5181`.

```bash
npm run build
```

Собранный сайт кладётся в `dist/` — это готовая статика, ей не нужен Node на сервере.
Проверить сборку локально:

```bash
npm run preview
```

Размеры на момент сдачи: HTML 18,4 КБ, CSS 15,7 КБ, JS 140 КБ (54 КБ в gzip).
Первый экран весит около 1,7 МБ, из которых 1,5 МБ — hero-плёнка.

## Плёнки

| Файл | Что это |
|---|---|
| `имя.webm` | VP9, отдаётся первым |
| `имя.mp4` | H.264, запасной вариант |
| `имя.jpg` | постер, показывается пока видео не загрузилось |

### Заменить плёнку

Положить новый исходник и перекодировать. Батч-кодировщик лежит в скилле:

```bash
python scripts/encode_plates.py --src <папка-с-исходниками> --out kedr/public/video --map map.json
```

`map.json` — это `{"имя-слота": "Файл_Из_Flow.mp4"}`. Скрипт делает mp4, webm и постер,
после чего **удаляет webm, если он вышел больше mp4**. Проверка не декоративная: VP9
проигрывает x264 на зерне и мелкой фактуре, а поскольку в `<source>` webm стоит первым,
браузер послушно скачал бы файл потяжелее. У `menu-01-margherita` и `menu-02-nigiri`
webm именно так и отвалился, поэтому в `index.html` у них только один `<source>` —
если перегенерируете эти плёнки и webm окажется меньше, строчку надо вернуть.

### Про склейку петли

Все десять клипов из Flow приехали восьмисекундными, и ни один из них не зацикливался:
камера за восемь секунд уезжает вперёд на несколько метров, поэтому в конце шёл жёсткий
скачок обратно на общий план. Исправлено кроссфейдом «хвост в голову» — клип заканчивается
тем же кадром, с которого начинается, и точки склейки просто не существует. Плюс у
`hero-room` срезаны первые 1,6 секунды: в них в верхнем левом углу висела подвесная лампа,
которая под затемнением читалась как грязь на объективе.

Если будете генерировать новые клипы — этот шаг придётся повторить, само оно не починится.

### Ещё одно про промпты Veo

В промпте `detail-cornicione` в описании грейда стояло «Kodak 2383». Veo отрисовал это
буквально: вписал в кадр киноплёнку с перфорацией и надписью **KODAK 2383** по левому краю
и «F/2.8 3489 5.21» снизу. Пришлось обрезать четверть кадра. Названия плёнок и объективов
в промпт лучше не писать, а в список запретов добавлять `no film strip borders, no sprocket
holes, no lens data overlay`.

## Перекрасить сайт

Всё в `src/styles/tokens.css`. Цвета там не выбраны на глаз — они сняты k-means по
кадрам самих плёнок.

| Переменная | Что делает |
|---|---|
| `--ground` | Фон. Тёплый почти-чёрный `#120b06`. **Не ставьте чистый `#000`** — он мажет на OLED и съедает тени, под которые снят материал |
| `--ground-cold` | Фон холодной секции, `#0a0a0d` |
| `--ink` / `--ink-muted` / `--ink-faint` | Три тона текста. Все три проверены на контраст, самый слабый даёт 4,7:1 |
| `--ember` | Тёплый полюс акцента, `#d89756` |
| `--steel` | Холодный полюс, `#b6bac6` |
| `--heat` | 0 = сталь, 1 = янтарь. Этим числом управляет скролл |
| `--font-display` / `--font-ui` | Cormorant Garamond и Golos Text |

Акцент один, но он меняет температуру: `--accent` собирается из `--ember` и `--steel`
через `color-mix`, а `--heat` двигается по секциям. В любой момент на экране ровно один
акцентный цвет.

Шрифты самохостятся из `public/fonts/` (кириллица + латиница, 95 КБ на четыре файла).
Никаких запросов к Google Fonts сайт не делает.

### Шкала температуры

Числа задаются в `src/content.js`, массив `SECTIONS`. У каждой секции своё показание,
подпись и значение `heat`. Если меняете заведение — меняйте и числа: приём работает
только пока цифры настоящие и выводятся из того, что человек видит на экране.
Подпись длиннее 12–13 знаков не влезает в ширину шкалы.

## Поведение

**Брейкпоинты.**
До 30rem (480px) из меню прячутся «Печь» и «Стойка», остаются «Меню» и «Контакты» —
иначе тумблер движения выдавливается за правый край и становится недоступен.
До 60rem (960px) закрепление секции «Печь» отключается, три абзаца просто ложатся
друг под другом; шкала температуры скрывается. Карточки меню: 4 колонки от 72rem,
2 колонки от 40rem, 1 колонка ниже.

**Reduced motion.** Вся хореография не запускается вообще — ни одного свойства не
трогаем, потому что состояние покоя в CSS уже финальное. Видео не играет, тумблер
показывает «Движение выкл.», но остаётся рабочим: посетитель может включить движение
сам, а не получить решение за себя.

**Тумблер движения.** Один контроллер на все десять плёнок, включая hero. Требование
WCAG 2.2.2 — у всего, что движется дольше пяти секунд, должен быть способ это
остановить.

**Ленивая загрузка.** Плёнки подгружаются за 350px до появления и ставятся на паузу,
когда уходят с экрана. На первом экране гидратирована ровно одна — hero.

## Что проверено

Считано в браузере, а не оценено на глаз:

- горизонтального скролла нет на 1440, 1024, 768, 390 и 360px;
- контраст посчитан для каждого текстового цвета относительно его реального фона,
  а над видео — по самому светлому кадру, до которого доходит клип. Минимум по
  странице 4,7:1, заголовок над hero 5,5:1, над печью 5,9:1;
- строки главного заголовка не переносятся ни на одной ширине (на 360px занимают
  259px из 305 доступных);
- зоны нажатия не меньше 44px;
- 404-х нет, ошибок в консоли нет;
- прелоадер снимается по таймеру-страховке, а не только по событию видео, поэтому
  не виснет в фоновой вкладке, где rAF заморожен.

Не проверено: собранная версия под `npm run preview` не прогонялась — в конце сессии
в окружении перестали запускаться процессы. Сборка проходит, `dist/` на месте со всеми
видео и шрифтами, но живой прогон продакшена стоит сделать одной командой перед выкладкой.
